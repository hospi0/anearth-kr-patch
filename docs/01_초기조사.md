## ★2026-09-26 대사 형식 (2차)
- **문자 코드**: 히라가나 = 반각 가타카나 1바이트(0xA1‥0xDF, 탁음은 ﾞ/ﾟ 덧붙임), 한자·가타카나·부호 = SJIS 2바이트, 줄바꿈 `\`,
  제어 = `%` + 바이트(`%K%L` 대사 앞, `%M` 끝 …). `tools/aecode.py`(enc/dec).
- **압축**: LZSS(Okumura 꼴 — 플래그 LSB 먼저·1=리터럴·참조 2B(오프셋 12비트 = a | (b&0xF0)<<4, 길이 (b&0xF)+3)·창 4096·시작 0xFEE).
  GAME.PRG 0xAF684 부터 풀면 이 장면 대사가 거의 다 나온다(`tools/lzss.py`).
  ⚠️그러나 일부 참조(예 «きゃははは»의 «ははは»)가 **아직 안 쓴 창 자리**를 가리켜 공백이 된다 → 창을 미리 채우거나(사전) 앞 스트림의 창을 이어 쓰는 방식으로 보인다. 미해결.
- 장면 묶음: GAME.PRG 0xAF05A‥0xDAE51 이 Work RAM Low 0x0024585A 에 **그대로(압축 상태)** 적재(파일 = RAM − 0x196800).
  앞부분은 절대 주소 포인터가 든 구조체·16비트 색표. 게임은 읽으면서 푼다(스냅샷 어디에도 풀린 대사 없음).
- 헛짚음: 0x543A 의 0x1000/0x0FFF = VDP1 명령표 코드, 0x8E190 의 0x0FEE = 그림 데이터.
- 다음: 압축 해제 루틴(SH-2)을 정확히 찾아 창 초기화 방식 확인 — 장면 적재 직후 스테이트, 또는 대사 한 글자씩 나올 때 스테이트 2장 비교.

## ★★2026-09-26 대사 형식 확정 (프롤로그 스테이트 — 풀린 대본이 Work RAM High 0x0608C000 에 있었다)
- **블록** = `[u32 LE 압축 크기][u32 LE 풀린 크기]` + LZSS. 예: GAME.PRG 0x4E1180(cs 0xF5A, ds 0x1988) → RAM 0x0608C000 과 **바이트 단위 완전 일치**, 소비 = cs.
- **LZSS**: 플래그 LSB 먼저·1=리터럴·참조 `a | (b&0xF0)<<4`, 길이 `(b&0xF)+3`·창 4096·시작 0xFEE ·
  ★**창 사전 채움**: 0x000‥0xCFF = 0‥255 각 13번 / 0xD00‥0xDFF = 0‥255 / 0xE00‥0xEFF = 255‥0 / 0xF00‥0xF7F = 0 / 0xF80‥ = 공백
  (`tools/lzss.py` prefill — 이걸 몰라서 «ははは» 같은 참조가 깨졌다).
- **풀린 대본 블록** = u32 LE 오프셋 표(첫 값 = 본문 시작, 예 0x324 → 201개) + 스크립트.
  문자: 히라가나 반각 1B · 한자/가타카나 SJIS · 줄바꿈 `\` · 제어 `%`+바이트(`%K%L…%M` 대사, `% 00 07 00` 주인공 이름 등).
- 아이템 설명 등은 GAME.PRG 에 이 문자 코드로 **비압축**(0x3CE3C 부근 «拾われた主人公のそばにあった\材質不明の短剣»).
- `tools/scanblocks.py` 로 PRG 전체 블록 목록(work/blocks_*.txt). 그림 블록도 섞여 있다 — 대본은 내용으로 가린다.
